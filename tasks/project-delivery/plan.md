# project-delivery 实施计划

2026-10-27。依据用户已确认的[交付规格](../../SPEC-project-delivery.md)及已有连续开发授权推进。检查点用于报告证据及修正实施问题，不重复请求开始下一小步的许可。完整任务状态只维护在 [todo.md](todo.md)。

## 交付顺序

先修复下载工程无法显式选择测试库的问题，再通过真实 Vue + Java 应用验证不透明来源预览，随后完成固定源码下载和恢复。新能力默认关闭；后台接口验证完成后，工作台集成归下一模块。

依赖：PD01 → PD02 → PD03（独立构建）；PD04 → PD05 → PD06 → PD07 → PD08（预览）；PD09 → PD10（下载）；PD11 → PD12（恢复）；PD03 + PD08 + PD10 + PD12 → PD13 → PD14（实际工程交付验收）。PD05/06 与 PD07/08 有消费关系，均按单代理顺序实施。每项最多约五个实现/测试文件；若超出，先将该项拆成有独立验收的子项，不堆积大提交。

## 保持的架构边界

- 执行模块只对原拥有者签发的准确运行句柄开放受限 HTTP 交换，不向交付层暴露端口或任意 URL。
- 预览授权内存保存十分钟，复核原会话及原进程。路径令牌与 Origin null 的权限各自独立；CSP sandbox 不允许 same-origin。
- ZIP 从固定源码树写出，保留文件字节和可执行模式；构建配置修正必须形成新版本，不能在导出时修改旧快照。
- 恢复走源码模块已有 CAS、幂等和异步协调器；不回滚数据库或启动进程。
- 不增加依赖、表、数据库、角色、域名、监听端口或子代理。不调用付费模型、不发送邮件、不推送或部署。

## 验证及资源

`N`：现有 Node 24.20.0 执行模板脚本测试。`J`：`sh .local/run-ex22-checks.sh ex22-delivery-<slice>.log '<focused selectors>' verify`，按任务实际测试名选择；runner 使用项目隔离 JDK 17.0.14 和已批准的 `atoms_verify_20261025_ex22` schema。只同时运行一个 Maven，包括浏览器夹具和原生构建。失败保留原日志，定位后才针对受影响部分重跑。

`B`：现有 8081/5174 Playwright 浏览器夹具，使用真实 Chromium。先以实际 Vue 打包产物和 owned Java 应用证明模块加载及 JSON 预检，而后补授权与故障边界。假上游只用于故障注入，不替代业务验收。

`A`：显式 `project-execution-contract` 原生 profile，复用 `.local/project-execution-acceptance.x5cvui` 的 A/B 配置及 18181/18182。已存在 V2 数据，不重放 V1 初始化或清理/repair。精确命令及输出路径随实际入口记录到验证文档；不在文档提交中触发原生构建。

独立下载验收先记录 A/B 数据，再用 A 的源码 ZIP、B_test 配置通过下载目录自己的 `scripts/build.mjs` 构建；原 B owner 停止后，用 B_app 配置在 18182 启动。仅添加自身验收记录，检查 B 原数据保留、A 不变、重启后新增记录仍在。旧失败证据和未决审计不改写。

## 风险与处理

| 风险 | 处理 |
|---|---|
| 内部 worker 掩盖下载脚本缺陷 | 先显式配置入口及独立 Java 测试配置；最后必须运行 ZIP 内自己的脚本 |
| opaque-origin 使 ES modules/API 不可用 | 将真实 Chrome 验证放在下载/恢复之前；仅精确令牌路径处理 CORS |
| 校验及读取各自用完三十秒 | 在执行入口共享单一剩余预算，取消读取，最后复核身份 |
| 代理写入成功后身份失效或超时 | 固定不确定结果错误，不自动重试，不声称撤销已发生写入 |
| ZIP 模式丢失、来源漂移 | 固定 STORED ZIP/Unix mode；标准解压器比对完整树并独立构建 |
| 原生验收污染已有业务数据 | 仅兼容 V2 新源码，保留快照，复用已授权角色，不清库 |

当前没有需要额外决策的规格问题。若需要新增持久资源或改变已确认安全边界，先给出具体变化再申请；实现细节继续自主处理。
