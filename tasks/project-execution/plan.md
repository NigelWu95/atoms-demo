## 1. 交付范围与组织

交付内部完整链路：不可变 Vue/Java/SQL 源码 → 受控依赖准备 → 实际测试与构建 → 封存 JAR → 本机 Java 进程 → HTTP 业务与数据库持久化验收。不是只增加状态接口或假进程测试。

唯一任务清单为本目录 [todo.md](todo.md)，使用 `EX01–EX30`、检查点 `C-EX01–C-EX10`。旧 `tasks/todo.md` 已使用 `PE` 表示工程导出，不能复用该编号；不覆盖旧清单、C-EB11 人工评审、源码/Agent 的验收记录及 OAuth 草稿。

本模块不接公开 HTTP 入口、不改工作台、不实现新预览代理/ZIP，也不自动调用模型修复。它提供交付模块所需的构建及运行身份；后续 `project-delivery` 和 `project-workbench` 再接实际预览与按钮。旧固定模板链路保持可用。

按已批准的顺序连续实施，检查点用于报告证据，不逐项询问是否开始。新增环境权限、依赖例外、真实模型费用、日常启用和部署另行确认；无法证明进程停止或数据兼容时停止相应执行，不用降级检查换取通过。

## 4. 核心实现决定

### 4.1 进程证据与总期限

优先给现有 `OwnedProcess` 增加窄的受控调用策略/中立结果适配，默认调用保持原 Agent 行为和错误码；不新抄一份子进程枚举、终止和 I/O 收尾代码。`Stopped` 仍只能由真正拥有进程的实现发行，源码租约的证据匹配规则不放宽。具体签名在 EX03 的小型契约测试中固定；若需要改变旧行为，先拆兼容改造并更新提供方规格。

构建与依赖准备各用单调总期限；阶段、源码读取、安装、检查共享剩余时间，取消不能刷新期限。`ProjectSourceReadGateway` 兼容重载传入 `SourceExecutionBudget`，下游仍受源码模块自身上限约束。查询接口不启动工具探测或 Git 写入。

常驻运行不把 120 秒启动期限当作整个应用寿命。执行线程在 `READY` 后继续持有进程和 I/O，直到停止或异常退出；健康检查结束不丢弃拥有关系。停止仍由相同拥有者完成；服务崩溃后不能从数据库 PID 重建此能力。

### 4.2 冻结输入与依赖策略

- 构建准入保存明确 `sourceVersionId`；出队后重新授权并读取该版本。所有文件 I/O、安装和构建在数据库事务外。
- 只向平台分配的任务目录物化完整快照；拒绝链接、硬链接别名、非法路径、模式或容量，比较源码字节/路径/模式。仅批准的输出目录可变。
- npm 清单、锁文件及 Maven 的父 POM/依赖/插件/仓库/配置输入经过维护者策略核对。模型可提出改动，但不能在工程中写一个批准文件替代审核。
- 平台固定 frontend 类型检查、lint、测试、构建的入口及参数；不直接执行可改写的任意 npm script。初始版本只支持已核对工具集合，超出支持范围明确拒绝。
- Maven 使用维护者工具、专用 settings/缓存和受控参数。禁止工程通过 `.mvn`、profiles、settings、扩展或插件参数悄悄带入另一个执行策略；解析不了则拒绝，不能只匹配 POM 字符串。
- 成功必须有本次干净输出目录的测试报告、实际测试数量和产物摘要；报告缺失、跳过或退出码不符不能标成功。生成测试仍可能写得不充分，甚至伪造报告，因此通过只代表受信样本的门槛，不是任意代码安全认证。

lock-only 是独立任务：批准待解析的清单/来源 → 编辑租约副本 → 固定锁文件准备 → 停止证明 → 只允许锁文件变化 → 发布新源码版。准备批准只允许解析，不自动批准未知的新锁图；新版本构建仍需匹配准确锁摘要的执行批准。依赖新增不得通过“重试构建”隐式获得执行权。

### 4.3 持久记录、并发与幂等

拟依次追加 V023 构建/事件、V024 依赖准备、V025 运行/绑定/迁移批准；实施前复查编号，不覆盖其他工作新增迁移。状态及关键关联有数据库约束，不能只靠内存 Map。

稳定幂等键按项目及操作类型划分；同键同输入重放原任务，包括进行中的任务，同键不同输入冲突。非正文幂等证据本期不自动过期。退出码、原始输出或模型文字不能直接修改成功状态。

锁顺序沿用项目行 → 对应任务/绑定 → 必要的全局准入锁；协调者先只读选任务，再按固定顺序领取。不能持有全局锁等待项目行。启动每个外部执行前先提交一次性执行意图；工作进程持有 root 文件租约与数据库协调权。未知执行占用相应容量及同项目阻断，不靠租约到期认定它已停。

构建默认 1 个活动、8 个等待，可配置 1–4；Agent 默认 4 不变。lock-only 准备与构建共享此执行容量和排队期限，避免借另一队列绕过限制；同项目二者互斥，准备还占源码编辑租约。已有运行可以在新版本构建时继续服务，换版时才停旧进程。

协调者必须在源码模块就绪后启动，先完成恢复再接新任务；关闭时先停止本模块再关闭源码模块。Agent 与执行器都依赖源码，不互相依赖；不因两者生命周期 phase 相同推断初始化顺序。

### 4.5 交付契约与诊断

`BuildView` / `RunView` 区分源码版本、构建版本、当前运行、最后成功构建，不用单个“已完成”覆盖它们。对外字段只含 ID、状态、阶段、错误码、时间及摘要；路径、JDBC、凭据和原始日志不进入 DTO。

交付消费者通过本模块内部受控句柄核对构建 ID、源码版本/树摘要、JAR 摘要及运行身份；调用者不能指定代理目标或文件路径。句柄不能序列化成长期访问权，每次访问重新校验所有权/归档及当前运行事实。下载读来源快照，不读可变构建 cwd；实际代理/ZIP 留给交付模块。

各阶段即有结构化事件，不到最后才补观测。每任务 1000 条/64 KiB，分页最大 100；仅接受有界相对文件名、行号、错误分类、阶段与数值。原始 stdout/stderr 只做有界解析/排空，不落库/回传；不把过滤敏感词当成可保存任意原文的许可。准备、构建、启动失败都不自动请求模型。
