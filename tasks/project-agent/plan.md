## 4. 一致性与权限实现细化

### 4.1 项目编辑租约

`source_edit_leases` 归源码模块所有，不引用 Agent 表，维持单向依赖。持久记录租约 ID、项目/所有者/任务、基线、状态、一次性执行身份、是否未决及结束证据摘要。活动项目唯一约束是跨 JVM 的保护，内存 Map 仅保存不可伪造的句柄发行关系。

V020 同时给 source_operations 增加可空租约关联：旧操作为空；新接受绑定租约。领取租约时拒绝尚未结算的既有源码写操作；已有租约时，所有新的普通写入、旧排队操作的准备/发布以及源码恢复均复查。只凭一个 task UUID、布尔 stopped 或裸 PID 不能放行。

锁顺序以 projects 行为起点，再取源租约/任务证据，最后取需要的全局准入或预算锁；不先持全局锁再等待另一项目行。Worker 可先只读选任务 ID，再在上述顺序中 CAS 领取。外部进程、文件复制及 Git 操作全部在事务外；并发与锁顺序用真实两连接测试验证。

### 4.2 一次性执行和停写证据

准入时在同一数据库事务中建立 Agent 任务与源编辑租约，避免已入队却无互斥，或拒绝任务却遗留锁。真正启动前原子预留 live run 额度及执行意图；启动失败也不自动返还已经预留的额度，未知结果不重跑。

执行适配器持有 Process 关系、单调 deadline 和受控读流。正常退出/取消后的结束证据通过内部不透明执行对象传递，不能从 HTTP DTO 或模型结果构造。启动到写入 PID 之间仍有崩溃窗口，因此 PID 仅作诊断，执行未决标记才是恢复依据。

封存前确认停止写入；源码接受完成后再把 source operation / version ID 记入任务结果。跨存储不声称原子事务：源码提交但任务响应丢失时通过绑定关系恢复。CLI 未决和 Git 未决不能相互清除。

### 4.3 取消、超时与生命周期

取消只持久设置请求，随后由拥有者停止进程；已提交版本优先反映真实结果。任务出队后共享 1800 秒期限，源码操作上限为 min(剩余任务时间, 300 秒)，源码排队时间也扣减；API_TIMEOUT_MS=300000 不能替代这个期限。

平台重启先完成源码恢复，再完成 Agent 恢复；停止时顺序相反。只保证有证据的自有进程处置，不声称能靠 Java ProcessHandle 抓住任何脱离父进程的恶意程序。无法确认退出则保留 NEEDS_RECONCILIATION、项目租约和证据，不自动强制解锁。

### 4.4 状态、事件和隐私

事件以平台阶段与白名单统计为主，不转发模型原始自然语言/源码/thinking。任务模型保存自己的输入、基线和结果元数据，不把完整工程塞回 PG。

保留期限已实现：Agent 启用后独立注册定时器，首次 60 秒后、以后每 300 秒执行最多 100 条的清理批次。按数据库时钟判定终态满 30 天，且编辑租约已释放才清除任务提示副本和事件正文；保留非正文幂等/版本/结算信息及事件序号水位。每条使用项目锁 → 任务锁，标记过期、清空提示、删除事件在同一事务；失败整体回滚该条。活动和待核对记录不自动清理，旧游标明确返回过期。Agent 关闭不注册或执行清理，不依赖旧生成器开关。磁盘证据没有自动 GC。

所有日志只含项目/任务 ID、阶段、码、耗时及计数。维护者名单与项目所有权是两次不同校验；新增名单不修改现有账号认证流程。默认不开放新 HTTP 路由，也不把已有 guest 身份当作新模式执行授权。

## 5. 配置与资源预算

沿用规格已确认值：128000 输出 tokens 目标、24 工具轮、默认 4 执行（可配置 1–8）/ 8 待处理、300 秒排队期限、1800 秒执行期限、300 秒 API 参数、最多额外 10 秒收尾；stdout 单行 4 MiB / 总量 64 MiB，stderr 256 KiB，总事件 4096 / 持久事件 256 KiB。真实有效模型参数必须由离线请求和之后的真实联调核验，不能静默下调后仍显示原值。

使用 `atoms.agent.*` / `PROJECT_AGENT_*` 独立配置：enabled、live-enabled、cli、state-root、maintainer-ids、max-live-runs、max-output-tokens、max-turns、task-timeout-seconds、queue-timeout-seconds、max-concurrent-tasks。并发值在调度器启动时读取，需重启生效；唯一协调者管理多个独立任务，不在 Worker 上持有跨任务的执行锁。同项目新需求在旧任务结束后基于最新版本重新提交，不自动积压过期基线。API 端点固定为规格中的 DeepSeek HTTPS 地址；没有可由请求指定的上游或命令参数。复用已有 DEEPSEEK_API_KEY，只在获准启动真实子进程时读取并交给该进程，不把它写入 settings 文件。

本计划补充的目录准入提案：Agent 私有状态根逻辑总量最多 1 GiB，文件系统至少保留 512 MiB；沿用源码根的已有容量策略，不把两者合并成一个错误的“硬配额”。启动、阶段边界和轮询时检查；同 UID 外部写入仍可能耗尽磁盘，这不是 OS 配额。实现中仅临时测试配置启用，日常 env 不改。需要放大上述预算时先记录原因并确认。

没有精确 API 请求计量和费用硬上限的承诺。live run 额度默认 0，以启动意图预留，不动旧 10000 次额度表；第三方模型的美元估算不作为结算或余额。真实联调另定费用边界。

## 8. 风险、停止条件和回退

| 风险 | 处理 |
|---|---|
| CLI 接受参数但不执行预期工具，或 DeepSeek 参数被改写 | PA03 先实测，记录实际差异；不静默换模型、降上限或扩权限 |
| restricted 不是 OS 沙箱 | 维护者 opt-in、无 Shell、私有配置、离线 canary；公开任意代码执行另行设计 |
| 机管策略影响认证或工具 | 拒绝启动并报告，不修改管理员策略或个人登录 |
| 源码租约与旧入口形成旁路/死锁 | 公共项目锁顺序、持久关联、两连接竞态及旧链路回归 |
| 默认关但新迁移破坏旧功能 | 只追加迁移，先专用测试库全量回归；关闭开关保留数据 |
| 正式源码已提交、任务结果丢失 | 通过持久源码操作关联补齐，不重新调用模型 |
| Agent 状态目录或日志填满磁盘 | 有界输入/流/准入，保留明确失败；不自动删历史让操作继续 |
| 原生模板仅通过内容校验 | 如实标未运行；后续执行模块验收前不提供“运行成功”状态 |
| CLI 费用估计与 DeepSeek 账单不同 | 任务次数不是请求次数/美元硬上限；真实联调先单独确认 |

回退采用禁用 Agent 并正常停止拥有者，源码协调者后停；保留新增表、租约、源码与证据。未决进程未结束时不能仅靠开关抹掉阻断，也不能降级到不识别租约的旧写入实现继续编辑。同机部署代码回退前必须先确认没有活动/待核对新任务。

新增依赖/工具安装、真实模型费用、拓宽工具权限、日常启用、执行新后端、远程变更或数据清理需要另外确认。无法验证权限或停写证据时停在对应任务，不通过删测试、跳过或放宽限制完成检查点。

## 9. 评审与完成定义

新增任务观测回答三个问题：任务当前卡在哪个阶段、是否已发出一次真实执行意图、是否已保存到确定的源码版本。任务 ID 作为 requestId，内部提交固定 entryPoint=internal_service；后续 HTTP 入口由服务端标记，不能让模型指定。阶段和稳定错误码进入持久记录，原始模型流、源码、提示、邮箱和凭据不进入日志。聚合执行次数与阶段耗时后续接入既有指标工具，不因观测新增外发依赖。

请评审本计划及任务，尤其新增的私有状态根 1 GiB / 512 MiB 准入预算。计划批准后拟连续完成 PA01–PA33，检查点用于汇报证据，不逐小项重复请求开始；仅在范围/授权变化或关键验收无法成立时停下说明。

完成 PA01–PA33 仅能交付“内部离线接入已验收，默认关闭”；PA-LIVE 未通过时保留真实模型未验收标记。源码保存、模板可构建、进程可运行、功能验收是不同结论；本模块不替后续模块提前作答。
