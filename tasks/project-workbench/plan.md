# project-workbench 实施计划

依据[规格](../../SPEC-project-workbench.md)及既有连续授权，顺序完成各项，验证后提交并继续，不逐小项请求开始。唯一状态表为 [todo.md](todo.md)。

先建立后端授权与只读源码入口，再以正式页面显示真实文件；随后接入需求任务、构建及依赖准备；最后补迁移/运行命令与已有交付接口，完成浏览器验收。每片约五个文件，较大页面拆为数据 composable 和呈现组件。沿用既有本机工具、元数据 schema 和 A/B 资源；单代理、单 Maven 串行执行。

依赖：PW01 → PW02 → PW03 → PW04；PW05 与 PW06 在页面基础后推进；PW07 → PW08 接运行；PW09 汇总真实浏览器及回归。遇到具体缺口时更新此规格和任务，不静默省略初始化、依赖、迁移或失败恢复状态。

主要风险：内部对象直接公开（只输出白名单 DTO）；后台长任务阻塞 HTTP（返回持久任务，页面轮询）；重复写请求（固定请求/键，显式重试）；版本切换误导（源码/构建/运行分别绑定）；跨账号迟到响应（请求代次与统一取消）；已运行应用在界面更新时重载（预览组件独立稳定 key）。

验证先定向 API 与 Vue 测试，再受控浏览器交互，最后原 A/B 应用的正式页面预览/下载。未改动已验证的 provider 不重复其全部原生构建；有失败或协议修改才扩大范围。所有首次失败保留，不能用旧报告冒充本轮结果。
