### 发现但未修复的业务缺陷

1. **新局第一次落盘缺失。** 全新访客进入后、不操作直接刷新，初始随机棋盘变化。生成的 `main.js` 在首次 `newGame()` 后只 `render()`，未调用 `save()`；第一次有效移动才写入数据库。这不满足“首次进入后的棋盘也可准确恢复”。
2. **快速连续操作存在旧 revision 排队。** 对独立验收访客的存档请求模拟 500ms 延迟，连续五次有效方向操作，观察到 PUT 先 200 后 409，页面明确显示保存冲突，刷新后不能恢复内存中的最后棋盘。`save()` 在排队时捕获 revision，上一笔成功更新 revision 后 `flush()` 仍提交旧 `pending.revision`；需改为发送时绑定最新已确认 revision，并保留未知结果/冲突处理语义，不能盲目覆盖远端状态。

两者属于这份模型生成的应用代码，不是预览和下载使用了不同实现；下载中 `main.js` 与已保存版本逐字节相同。没有静默修补下载副本、绕过数据库冲突保护或增加模型调用。本轮为部署和验收，尚未授权后续业务修复；修复后应重新保存版本、构建并复验下载包，不能沿用当前包的通过记录。

## 首次失败与修正

1. Spring Repository 被代理后，调度器直接访问其字段触发 NPE。真实 Spring 回归先复现，再改为仓储方法调用；启动、就绪与停止均修正。
2. 端口探测把 TIME_WAIT 误判为活动监听者。真实 socket 测试先失败，再使用匹配服务重启语义的 SO_REUSEADDR；仍拒绝真正被占用的端口，不杀其他进程。
3. 外层测试工具整组终止过早，监督器未能写退出证明，两个测试实例保留 INTERRUPTED 占位。系统没有自动清空或重复启动；只读核对并经明确批准，仅解除这两条测试记录的占位，保留历史和全部业务数据。测试脚本改为正常停止实例后再退出平台；生产自动恢复规则未放宽。
4. 浏览器测试上下文缺少 baseURL，修正测试配置；状态夹具误用 `text` 而非 `title` 导致空标签，被 axe 检出，修正输入，不关闭无障碍规则。
5. 实例轮询重传相同下载目标，引发前端 watch 重置/取消下载。增加失败回归并改为分别监听稳定标识；真实 Chrome 下载已通过。
6. 子进程测试脚本嵌套引号错误，加入语法检查并用 JSON 序列化构造参数；没有通过放宽进程退出要求让测试变绿。
7. 手机全页截图中的离屏 iframe 未绘制，直接等待其内部控件稳定也超时。改为先滚动外层 iframe 到可视区，再实际输入并截图，320/390px 均通过；没有屏蔽控件交互断言或修改生产渲染逻辑。
8. 原发布、下载、检查报告用例把完整业务流程与多次 axe 扫描放在单个 30 秒预算内，回归出现累积超时。将各尺寸扫描拆成独立用例，保留所有原业务断言、扫描尺寸、无障碍规则与原超时；原 20 项套件因此拆为 33 项，不以增加数量声称新增 13 项产品能力。
