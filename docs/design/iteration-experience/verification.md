## 失败、原因和修正

1. 早期完整后端检查使用系统 Node 20，已有构建环境测试要求锁定 Node 24.20/npm 11.19；切换本次命令 PATH 后通过，没有修改全局 Node 默认或降低版本断言。
2. 沙箱禁止本机 Socket/浏览器请求及 Mockito 附加进程，导致 EPERM；获得执行权限后原命令通过，没有切换真实数据库或关闭测试。
3. 草稿审阅发现：非零 revision 的空远端内容被当成首次草稿；用户点击重读后输入被覆盖；会话重验证短暂停用目标时丢失未保存提醒。分别加入回归测试，保留输入、冲突提示和暂停提醒；身份真切换清空缓冲才取消提醒。
4. 原 `App.spec` 没有草稿接口替身，离开时触发 jsdom 未实现的 confirm，却因缺少路由断言产生假阳性。补齐草稿读写替身、等待保存并断言确实返回首页，完整回归不再有该警告。
5. 原 `todo-history` 夹具两个版本完全相同，因此不应出现差异。新增独立 `todo-review` 有差异夹具，保留历史恢复测试行为。Headless Chrome 跨 iframe 子元素滚动曾等待稳定性超时，改为滚动宿主 iframe，并保留真实子页面内容断言；未提高超时或删去可访问性检查。
6. 无权访问文案从“当前访客”调整为“当前身份”，适用于已注册账号；同步精确文案断言，仍验证跨身份不能显示项目或 iframe。新建后立刻导航的测试等待真实草稿保存，未绕过离开保护。
