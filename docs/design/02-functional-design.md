# 02 · 功能设计

## 1. 产品定义

暂定名称 **Atoms Demo Studio**。目标用户为想快速制作内部工具、展示页面或小型应用的人，以及需要验证生成效果的评审。

用户输入自然语言，平台形成简要计划、生成真实源码，展示运行中的页面；用户继续描述修改，平台保存新版本。生成的待办、表单和看板等应用可通过平台保存数据，并有稳定的公开访问链接。

设计范围：单人创建项目、小规模同时体验、现代桌面浏览器编辑、生成页面适配移动端。首版不承诺生成任意 SaaS 或实现原站所有功能。

## 2. 原题要求与验收映射

| 原题要求 | 本设计交付 | 验收方式 |
|---|---|---|
| 可运行网页应用 | Vue 工作台 + Spring Boot API + 数据库 | 外部浏览器打开线上平台 |
| Agent 驱动代码生成 | Planner → Builder → Validator，真实模型与工具动作 | 非预置提示产生对应的新源码 |
| 可视化展示 | 沙箱内实际运行 HTML/CSS/JS | 操作按钮、筛选和表单 |
| 类似 UI 交互 | 首页输入、聊天与预览、步骤卡、版本、发布 | 完整走一遍用户旅程 |
| 真实交互 | 新建、生成、修改、保存、恢复、发布 | 用户操作改变真实服务端状态 |
| 数据持久化 | 项目/消息/运行/版本；生成应用业务状态 | 刷新、重新登录或服务重启后按身份恢复 |
| 基本使用流程 | 访客初始化和项目主流程；注册为增强 | 首次进入即可完成生成 |
| 至少一个延展方向 | P1 优先做历史版本恢复 | V1 → V2 → 恢复为 V3 |
| 在线访问链接 | 平台 URL + 生成应用 URL | 无痕窗口分别验收 |

其中“重新登录恢复”仅适用于已经实现 P1 账号功能的版本。P0 访客在同一浏览器 Cookie 未失效时恢复；清理 Cookie 或换设备不会找回原访客身份。

## 3. 能力模块与依赖

依赖箭头表示“依赖于”。本表是后续实现的能力索引。

| 模块 ID | 职责 | 依赖 |
|---|---|---|
| identity-project | 访客会话、项目归属和列表 | — |
| artifact-version | 源码快照、当前版本、历史版本 | identity-project |
| agent-run | 请求、规划、生成、校验、事件和取消 | identity-project、artifact-version |
| app-data | 按项目/环境/访问者保存 JSON 状态 | identity-project、artifact-version |
| preview-runtime | 隔离运行、SDK、日志、预览报告 | artifact-version、app-data |
| publication | 固定版本公开访问、更新和下线 | artifact-version、preview-runtime |

artifact-version 不调用 agent-run；由 agent-run 通过接口提交产物，避免循环依赖。publication 复用预览外壳和数据桥，不复制运行机制。

建议构建顺序：项目和快照 → 带示例产物的预览/数据链路 → 接入真实生成 → 发布 → 版本恢复。示例产物只用于开发验证，正式生成入口必须调用模型。

## 4. 用户与权限

| 身份 | 权限 |
|---|---|
| 项目创建者 | 创建/查看自己的项目，提交生成、查看源码、发布、恢复 |
| 公开应用访问者 | 运行已发布版本，保存自己在该应用中的状态 |
| 其他平台用户 | 不能访问他人的聊天、未发布源码、运行记录或预览数据 |

P0 以随机访客身份提供进入体验，服务端会话与项目归属持久化。P1 可以升级为邮箱密码账号，升级保留 userId，因而不需要迁移项目所有权。不引入组织、多工作区和 RBAC 管理页。

公开应用可免注册打开。其数据按访问者隔离，同一个链接下的两个访客不会默认看到彼此的待办事项。首版不把它称为“协作看板”。

## 5. 范围与优先级

### P0：交付闭环

| ID | 功能 | 明确范围 |
|---|---|---|
| F01 | 访客初始化 | 创建服务端身份与会话，同浏览器恢复 |
| F02 | 项目管理 | 列表、新建、打开、重命名；无复杂文件夹 |
| F03 | 提示输入 | 多行文本、示例提示、输入校验 |
| F04 | 真实代码生成 | 简要规划和代码输出两个模型阶段 |
| F05 | 进度观察 | 阶段/产物/错误事件；刷新后恢复状态 |
| F06 | 运行控制 | 取消、失败后重新提交；每项目一个活动任务 |
| F07 | 交互预览 | 桌面/移动宽度、刷新、独立预览页 |
| F08 | 源码查看 | 固定几个文件的只读代码视图 |
| F09 | 继续修改 | 对明确基线版本修改，生成完整新快照 |
| F10 | 平台持久化 | 项目、消息、运行记录、事件与版本 |
| F11 | 应用状态 | JSON 状态读写、保存状态反馈与冲突提示 |
| F12 | 发布访问 | 首次发布、更新、下线、复制链接 |
| F13 | 在线交付 | 容器部署、持久卷、HTTPS 和外部访问验证 |

### P1：按剩余时间排序

1. **版本恢复**：历史列表、历史代码预览、恢复为新版本。优先作为延展亮点。
2. **错误辅助修复**：真实错误日志自动填入修复请求；用户点击后发起一轮新生成。
3. **注册登录**：用户名或邮箱密码注册、登录、退出；不接邮件验证码与 OAuth。
4. **源码导出**：ZIP 包含源码和数据 SDK 依赖说明；不能声称离线运行即可获得平台数据库。

P1 是候选增强项，不承诺 8 小时内全部实现。至少优先交付版本恢复；其余以 P0 稳定为前提。

### P2：后续版本

点选元素后定向修改、手工源码编辑、截图输入、Vue/React 多文件编译、Remix、用户自定义主题、Race Mode、多人编辑、完整生成应用认证、文件存储、支付、GitHub 同步、自动部署独立后端。

## 6. 页面与路由

| 路由 | 页面 | 主要内容 |
|---|---|---|
| `/` | 首页/项目入口 | 欢迎文案、主输入框、示例提示、最近项目 |
| `/projects` | 我的项目 | 项目名、更新时间、生成状态、发布状态 |
| `/projects/:id` | 工作台 | 对话、步骤、预览、源码、版本、发布 |
| `/preview/:projectId/:versionId` | 独立预览外壳 | 需项目权限，仍通过沙箱运行 |
| `/a/:slug` | 公开应用外壳 | 仅加载已发布版本，不展示聊天或编辑控件 |
| `/login`、`/register` | P1 账号页 | 登录、访客升级、退出 |

这些路由属于 Demo，不表示原站路由。

### 6.1 首页

- 左侧约 224px 导航；主区域给需求输入足够空间。
- 提供“待办清单”“活动报名表”“个人作品集”三个提示示例，只填充提示，不直接冒充生成结果。
- 输入框支持 Shift+Enter 换行，Enter 发送；中文输入法组合期间不触发发送。
- 提交后先创建项目并获得 ID，再进入工作台创建运行；失败时保留输入。
- 首次访客初始化失败时显示可重试状态，不展示可发送但实际无身份的空壳。

### 6.2 工作台

```text
┌──────────────────────────────────────────────────────────────────┐
│ ← 我的项目   项目名        当前 V2 / 线上 V1      版本    发布更新 │
├─────────────────────────┬────────────────────────────────────────┤
│ 对话与真实执行过程       │  预览 | 代码      桌面/手机  刷新  ↗   │
│                         ├────────────────────────────────────────┤
│ 用户：创建待办工具       │                                        │
│ Planner：计划摘要       │            可交互应用                  │
│ Builder：正在生成       │                                        │
│ Validator：契约检查     │                                        │
│ V2 结果卡               ├────────────────────────────────────────┤
│                         │ 预览检查 / 错误 / 数据保存状态         │
├─────────────────────────┤                                        │
│ 描述下一步修改…  发送    │                                        │
└─────────────────────────┴────────────────────────────────────────┘
```

宽屏下对话约 360–420px，其余给预览；窄屏使用“对话 / 预览”切换，避免强行挤压双栏。发布是主要按钮，查看源码为次级入口。P0 不要求拖拽分栏。

空项目显示提示；首次生成展示阶段；后续生成保留上次结果并标注“正在生成新版本”。不要把未完成代码片段实时执行到预览中。

步骤卡展示可公开的计划、执行动作与结果摘要，不展示模型内部推理。卡片上的角色数量不意味着运行了同等数量的独立模型。

### 6.3 源码与版本

源码视图显示 `view.html`、`styles.css`、`main.js` 与 `manifest.json`，附版本号。首版只读；历史版本不会自动成为新修改的基线。

P1 恢复操作复制选中源码为一个新版本。例如 V1 → V2 → 从 V1 恢复得到 V3，保留 V2。弹窗说明恢复代码、不回滚业务数据、不自动发布。历史预览默认使用初始示例数据并禁用服务端写入，避免旧代码改坏当前数据。

### 6.4 发布面板

- 未发布：选择当前版本，首次发布生成稳定 slug。
- 已发布：同时显示编辑版本和线上版本；只有显式更新才替换线上版本。
- 发布期间按钮禁用；失败保留旧公开版本。
- 支持复制公开 URL 和下线。访客打开下线链接得到明确不可用页面。
- 发布前展示预览检查结果和手动体验提示；“检查通过”只覆盖已执行的项目，不声称全面测试。

## 7. 核心用户流程

### 7.1 首次生成

1. 用户打开首页，服务端初始化或恢复访客会话。
2. 输入“做一个可添加、完成和筛选任务的待办应用”。
3. 创建项目与运行记录；界面显示已接收。
4. Planner 给出需求摘要、页面和交互要点。
5. Builder 输出完整源码、初始状态和支持的数据契约。
6. Validator 检查结构和限制，通过后保存不可变版本。
7. 前端解析 JS 语法并在沙箱运行；显示独立的预览检查结果。
8. 用户添加任务，写入服务端，刷新后任务仍在。

### 7.2 对话修改

1. 用户输入“增加优先级筛选，保留现有任务”。
2. 请求带 `baseVersionId` 与当前 `projectRevision`。
3. 服务端验证基线仍为当前版本，并锁定本轮任务。
4. 模型收到基线源码与新要求，输出完整新版本。
5. 新版本不含真实访客数据，现有业务状态不被模型覆盖。
6. 新页面兼容旧状态，展示新增筛选；若需要破坏性状态结构变更，首版拒绝并要求改为兼容设计。

### 7.3 发布与继续编辑

发布 V1 → 无痕窗口打开 `/a/slug` → 访客操作并保存自己的数据 → 创建者生成 V2 → 公开页面仍为 V1 → 创建者发布更新 → 公开页面加载 V2、同一访客数据保留。

预览数据不复制到线上，线上已有数据不因更新而重置。没有数据的访客才使用版本中的 `initialState`。

## 8. 状态与异常体验

| 场景 | 界面行为 | 服务端行为 |
|---|---|---|
| 模型连接慢 | 显示当前阶段和已等待时间 | 超时到期结束，提供错误代码 |
| 模型返回无效产物 | 展示校验错误与一次修复状态 | 最多一次有限修复，失败不覆盖当前版本 |
| JS 语法错误 | 预览错误面板，可复制错误 | 保存检查报告，源码产物仍可审查 |
| 运行时错误 | 指出报错阶段，保留代码与历史 | 不把预览报告当作可信业务输入 |
| 用户停止 | 显示取消请求，随后终态 | 尽力取消上游，禁止晚到结果成为当前版本 |
| 页面刷新/断网 | 重载运行状态与事件 | 任务不依赖浏览器连接存活 |
| 重复发送 | 按钮禁用；网络重试复用请求键 | 同一意图返回同一 runId |
| 并发修改 | 提示已有任务或版本已变化 | 409，不静默覆盖 |
| 应用数据保存失败 | 显示未保存，可重试 | 不返回虚假成功 |
| 两标签同时保存 | 告知存在更新，重新读取 | 基于 revision 返回 409 |
| 生成期间关闭浏览器 | 回来能看到结果或失败原因 | 继续生成；预览仍待检查 |
| 服务重启中断生成 | 显示任务中断并可重试 | 标记 INTERRUPTED，不无限“运行中” |

## 9. 可支持的生成应用

适合：任务清单、习惯打卡、个人记账、个人看板、交互报价计算器、问卷草稿、展示页面。复杂度限制为一个页面内的多个视图、有限状态、原生 JS 与 CSS。

暂不支持：真正多人共享协作、实时消息、支付结算、OAuth、任意文件上传、生成独立服务进程、用户随意添加 npm 依赖。这些限制必须在帮助说明和模型契约中保持一致。

首版表单保存仅保存当前访问者的草稿或记录，不应将其展示为已经给组织管理员提交了真实订单。

## 10. 质量与完成标准

以下为待验证目标，不是测试结果：

- 三类代表提示至少各跑通一次真实生成，至少一个应用完成两轮修改。
- 平台刷新、服务重启后，项目和版本仍可读取；访客会话在有效期内可恢复。
- 任务、表单或其他业务状态可以写入、刷新读取；另一个访问者的数据不会混入。
- 生成失败不改变上一版源码，也不改变已发布版本。
- 桌面编辑主要功能可键盘操作；生成页面检查 390px 与 1440px 宽度。
- 提交操作在正常网络下尽快返回 runId，目标 1 秒内；模型阶段以真实等待状态反馈，不保证固定生成时长。
- 提交时平台和公开应用 URL 均可从无痕窗口访问；模型不可用时界面清楚说明。
- P1 版本恢复完成时，证明历史保留、数据保留、公开版本不自动变化。

## 11. 设计风格

采用安静的深色工作台、清晰的字体层级、轻量边框和一个强调色。Agent 用小型身份标记，正文以产物和结果为中心。生成页面按用户要求独立设计，不能让每次输出都退化为相同卡片布局。

加载、空态、异常、取消、保存中和已保存都要有对应状态。第一版不展示无法使用的竞速、团队设置或集成按钮。
