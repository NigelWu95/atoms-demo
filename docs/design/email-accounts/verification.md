# 邮箱账号本地验收记录

日期：2026-10-16。基线 `c551a76`，分支 `feature/standalone-engineering`。本文记录本地 QQ SMTP 适配、免密码邮箱账号、会话与前端隔离验收；该阶段未推送或部署。用户随后自行配置，另行授权的真实邮件验收见下文。再后续授权的 GitHub 同步与云部署已完成，独立记录在[云部署文档](https://github.com/NigelWu95/atoms-demo/blob/main/docs/cloud-deployment.md)，不将本地证据冒充云端真实收信。

## 自动验收的环境与隔离

- Java `17.0.5-oracle`、Node `24.20.0` / npm `11.19.0`，PostgreSQL `17.11`。
- 数据库只用 `atoms_demo_test` / `atoms_test`，HTTP 集成测试随机端口；浏览器用 8081 / 5174 与独立 Chrome。
- Chrome DevTools MCP 当前不可用，按浏览器技能使用仓库现有 Playwright 真浏览器替代。不是 jsdom 冒充浏览器。
- `EmailFixture` 只在 test classpath，验证测试数据库、角色与回环绑定后提供发件器；捕获随机测试码，只允许发起挑战的身份读取。
- 不连接真实 SMTP，不调用模型，不重启日常 8080 / 5173 或本机应用进程，不访问远程服务器。

HTTP / 数据库测试覆盖：

- 只保存 HMAC，不保存明文码；过期、重放、跨会话、输错 5 次不能认证。
- 一个验证码并发验证只有一个成功，预算与错误次数不因业务异常回滚。
- SMTP 失败不建账号；失败重发保留前一次有效码，成功重发只替换自己的会话，不使另一浏览器的码失效。
- 新邮箱保留 owner UUID 和已有项目，已有邮箱切换原账号，陌生访客不能读取项目。
- Cookie / CSRF 轮换，退出、旧 Cookie 重放、已撤销但重新落库的旧会话、账号旧 ROLE_GUEST 上下文均被拒绝。
- 同 UUID 注册保留本机预览桥；跨账号切换清除旧会话桥。
- 退出结束旧 SSE，不取消后台生成；原 SSE 回放、游标和心跳测试继续通过。
- 严格字段、重复 JSON 键、4 KiB 认证请求上限、CSRF、429 / Retry-After / no-store。
- 公网 HTTP 不能通过 Host / X-Forwarded-* 字符串冒充回环；真实 HTTPS 与本机 HTTP 按契约处理。
- 到期元数据有界清理，不删除账号、项目或有效挑战。

浏览器邮箱流程验证了首次注册前后项目归属、另一标签页的身份与草稿清理、退出后旧项目不可见、另一独立浏览器验证码登录恢复原项目、刷新继续登录、错误验证码与键盘 Enter 提交。真实等待服务端 60 秒冷却，没有为了测试跳过冷却。UI 使用现有深色/浅绿样式；桌面与手机截图已人工检查，最终布局覆盖 320 / 390 / 1440px，axe 按 WCAG 2 A/AA、2.1 AA 检查。

## 发现并修复的问题（保留失败记录）

1. Maven Central 对邮件依赖返回 429。只用忽略提交的临时 Maven settings 改到 Google 的 Maven Central 镜像获取相同 BOM 版本；没有更改项目依赖版本、全局 Maven 配置或关闭 TLS。
2. 沙箱禁止数据库 socket；按权限机制运行隔离测试，没有绕过限制。完整后端首次的本机构建环境测试使用了不符合项目版本的 Node，显式使用既有 Node 24 / npm 11.19 后通过。
3. 清理测试漏填 schema 要求的 `created_at`，补齐测试数据；未放松生产约束。
4. Playwright 就绪探针受宿主代理影响，误判 5174 可用而 Chrome 连接被拒绝；在测试配置中为本机地址补 NO_PROXY。一次诊断 DEBUG 环境变量也触发了 Spring debug，只涉及隔离测试凭据；正式复测移除此变量，操作文档明确禁止认证正文调试。
5. 发码后尝试聚焦尚未解除 disabled 的验证码输入框，真实 Chrome 捕获；改为先解除 busy 再聚焦。
6. window focus 也会在离开 iframe 时触发，导致过度复核并销毁预览/表单。第一轮运行时回归出现 9 项失败；改为 visibilitychange / pageshow 复核，普通焦点移动不切换身份；复核时隐藏并保留组件，真正身份改变/失败再销毁。补两项先红后绿单元回归，原浏览器断言和超时不降低。

## 真实 QQ 邮件与本地账号验收（2026-10-16）

代码版本 `4da9f0d`。用户已在忽略提交的 `.env.local` 填写 QQ SMTP 与独立 HMAC 配置，并明确指定受控 Outlook 收件邮箱。未由工具回显私有配置内容；公开记录不包含完整收件地址、验证码或其他认证信息。

1. 使用生产 `SmtpEmailCodeMailer` 的配置进行连接检查：QQ 465 隐式 TLS、证书/主机名及 SMTP 认证通过。此连接检查不发送邮件。
2. 本地启动生产 JAR（8080，仅监听回环）及前端（5173），日常 `atoms_demo` 库增量应用 V013/V014；未删除已有项目。健康接口返回 `UP`，账号能力返回 `emailCodeEnabled=true`。
3. 独立 Chrome 打开真实 `/account` 页面，向用户指定收件人点击发送一次，没有自动重试。发送接口返回 201，验证码输入可用；有效期仍为 10 分钟。仅该响应不能证明最终收信。
4. 用户收信并自行在窗口输入验证码。只观察到验证响应状态 200，没有读取或记录验证码；用户随后确认「测试 OK」。这证明本次真实投递及验证码登录成功，不是测试发件器代替。
5. 收尾再次只读检查 8080 健康与 5173 账号能力，均正常。没有再次发信、读取收件箱、访问日常浏览器资料或调用模型。

本次邮件测试的后端启动参数为 `--atoms.generation.worker-enabled=false --server.address=127.0.0.1`，只影响该运行进程，不修改私有模型配置、额度或默认行为。恢复正常生成前需检查活动任务并恢复日常启动方式；本记录不是完整生成环境验收。

真实邮件下的退出后再次发码登录未单独复测；退出、重登、跨浏览器恢复与项目归属已有上文测试发件器的真实浏览器覆盖。没有做多收件人、批量发送、长期投递率或云服务器 SMTP 验收；远程版本与配置保持不变。

## 审查结论与未覆盖边界

按安全与代码审查技能检查了所有权、短事务、账号认领、撤销、严格输入、有限发信、日志脱敏、模板导出与前端迟到响应。SMTP 凭据只由维护者提供，默认不开启；新增依赖仅 Spring Boot BOM 管理的 mail starter。未改变数据库/模型私有配置、导出模板、模型额度或服务器配置。

这是低流量 Demo，不是完整商业身份系统：认证短事务使用一个 advisory lock，会话检查增加数据库读取；未做容量压测、高可用、外部依赖漏洞扫描或规模化邮件投递测试。账号邮箱持续保留，未实现换绑、自助删除和生产备份删除流程；公网 HTTPS 尚未配置。自动验收及一次真实邮件登录不证明这些项目已完成。
