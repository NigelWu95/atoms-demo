# 邮箱验证码账号实施计划

用户已于 2026-10-16 批准规格，并明确一次性完成规划、实现及本地测试，不再逐片等待批准。进度唯一记录在本目录 todo.md；不覆盖既有工程任务或暂缓的 OAuth 任务。

依据：[账号规格](https://github.com/NigelWu95/atoms-demo/blob/main/SPEC-email-accounts.md)（待推送）。沿用 Java 17 / Spring Boot 3.5.16 / Vue 3.5.43，新增依赖仅 Boot 管理的 mail starter。

顺序：邮箱输入与配置 → SMTP 适配 → 账号/验证码事务 → HTTP/会话 → 前端 API/页面 → 真实数据库与浏览器验收 → 使用文档。实施阶段每片测试先红后绿，不发送真实邮件、不重启日常进程、不调用模型、不部署。后续用户完成本地配置并指定收件人，另行开展一次真实邮件和登录验收；范围与结果见本目录 verification.md，不扩大到推送或部署。

设计细化：

- PostgreSQL 短事务采用固定认证 advisory lock 串行化验证码预算/消费/账号认领。这是低流量 Demo 的简单正确性取舍；SMTP 始终在事务外，锁/SQL 有限超时。未来高流量再改细粒度锁。
- 增加短期撤销会话 ID 摘要记录，并在请求及 SSE 读取时检查；账号行存在但会话仍为 ROLE_GUEST 时拒绝，防止并发旧访客请求重新保存会话后访问升级账号。
- 发送只接受固定模板和单个规范收件人，真实适配使用 465 TLS 和证书主机名校验；测试在 sender 边界替换，不在正式配置留下明文 SMTP 后门。
- 界面沿用现有暗色/浅绿 token，单列邮箱表单和明确的访客数据提示；不重做首页。账号切换清空内存数据、终止旧页面请求，跨页签仅广播失效通知。
- 观测问题：邮件是否被 SMTP 接受、失败发生在哪个阶段、耗时是否异常、验证是否受限。以 requestId、固定事件/结果码及耗时记录，不输出邮箱/邮件/凭据；不引入新的遥测服务。
- 对外 HTTP 默认不启用账号发送/验证；本机回环例外。按用户随后要求提供显式 HTTP 演示开关，统一作用于认证和已登录会话，保留其他防护；当前服务器不变更。

验收遵循规格 §9。测试 SMTP 不等于 QQ 实际收信；缺授权码时只把真实收信一项标待验。风险：个人邮箱反滥用/额度、邮箱送达未知、并发会话撤销和前端串号；不通过关闭安全控制消除失败。
