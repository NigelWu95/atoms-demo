# ADR-001 · 以受控应用生成为核心的 Demo 架构

状态：Proposed。日期：2026-10-07。

## 背景

挑战要求在建议 6–8 小时专注开发时间内交付可在线体验的 Agent 应用生成平台，并具备交互与持久化。用户偏好 Spring Boot + Vue，并希望比较 Go。参考产品同时包含协作、云后端、设计编辑和发布等大量能力，无法把全部能力都作为首版承诺。

## 决策一：Spring Boot + Vue 模块化单体

选择理由：贴合用户偏好；以现有熟悉度缩短验证周期；任务、数据和发布在单一服务内更容易处理事务边界。

替代方案：Go + Vue、Node/TypeScript + Vue。Go 在已有脚手架且更熟悉时可以替换；Node 在需要大量前端编译工具且开发者熟悉时有吸引力。当前没有证明换语言能提高交付成功率的具体证据。

后果：使用 JVM 运行环境；后期前端编译可能增加 Node worker。保留稳定 HTTP/SDK 契约，避免将前端绑定到 Java 特有对象。

## 决策二：生成静态 Web 代码，平台提供动态数据服务

选择理由：真正生成并运行代码，支持实际交互与持久化，同时把执行环境限定在可实现范围。

替代方案：生成完整 Vue 项目并构建；生成前后端项目并为每个项目启动隔离容器；仅输出 JSON UI Schema。前两种增加构建、依赖和调度成本；纯 Schema 的自由度和代码生成展示力较弱。

后果：首版只支持 HTML/CSS/JS 和受限数据 SDK；不能宣称支持任意 npm 包、独立服务器逻辑或完整 SaaS。未来通过 runtime 类型与 Artifact 契约扩展。

## 决策三：真实两阶段模型工作流与程序校验

选择理由：计划、生成、校验都有对应实际行为，易于定位错误；无需在首版引入复杂自主 Agent 框架。

替代方案：单次请求直接生成；多个独立智能体自由协作。前者可作为内部简化，但过程可解释性弱一些；后者对上下文、调度、费用和终止条件要求更高。

后果：不能宣称多个角色就是独立自主 Agent。错误修复有上限，结构通过和实际运行正确分别记录。

## 决策四：PostgreSQL 快照、事件与受限 JSON 状态

选择理由：同一数据库保存平台资料、不可变代码快照、运行事件和小型应用数据，减少部署组件。幂等与 revision 冲突可通过数据库原子约束实现。

替代方案：SQLite 文件库；Redis + 对象存储 + 外部任务队列；生成数据库表。SQLite 适合更简单单进程方案，但需处理持久盘与写并发；分布式组件和动态建表扩大首版范围。

后果：应用状态不是通用关系数据库，不适合大量记录、复杂查询和多人协作。源码与业务数据版本分离，恢复代码不意味着恢复数据。

## 决策五：数据库任务状态 + SSE 观察

选择理由：长任务独立于浏览器连接，回放事件可以恢复界面。用户重复请求通过幂等记录命中同一 run。

替代方案：把生成绑在一次流式 POST 上；WebSocket；外部消息队列。前者恢复与重试复杂，后两者在当前通信方向和规模下不是必要前提。

后果：单实例可以使用固定 Worker；多实例前必须增加 lease/心跳与协调。供应商请求超时后结果未知，不自动假定可以无成本重试。

## 决策六：独立运行文档策略与显式发布

选择理由：生成内容与宿主 DOM/凭据分离；运行文档使用响应级 CSP sandbox，公开访问复用可信外壳；发布指针与编辑指针分开。

替代方案：直接将生成 HTML 插入宿主，或在宿主同源页面不加限制运行；srcdoc 继承宿主 CSP 后临时放宽全站规则。这些方案使边界难以验证。

后果：数据读写需要受限通信桥；P0 不能承诺任意恶意代码的资源隔离或完全阻断网络。完整开放平台应采用独立运行域、受控构建与更强执行隔离。

依据：[CSP sandbox](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox)、[CSP 继承规则](https://www.w3.org/TR/CSP3/#csp-inheriting-to-avoid-bypasses)。

## 重新评估条件

- 目标明确要求生成独立后端及真实多用户业务系统。
- 开发时间扩大，允许配置和验证构建沙箱。
- 已有可复用 Go/TS 工程显著减少集成时间。
- 实际用户数据或并发超过 JSON 状态和单实例容量。
- 公开使用范围扩大，需要更完整额度、资源隔离和运行环境。
