# 完整工程源码模块 · 使用与维护

本模块是供后续 Coding Agent 使用的内部源码管理能力，默认关闭。它不切换现有网页、预览、下载或发布流程，也没有公开文件写入 API。实际验证结果见 [验收记录](project-source-verification.md)，范围见 [规格](../SPEC-project-source.md)。

## 保存了什么

新模式把 Vue、Java、SQL、依赖声明和非敏感配置保存为磁盘上的不可变 Git 版本。PostgreSQL 只保存项目归属、版本/父版本、Git 对象引用、完整树 SHA-256、文件数量、字节数、操作状态和幂等记录，不保存完整工程字段。

旧三文件产物仍按原方式保存。显式导入指定旧版本，会把该产物与指定摘要的工程模板固化成新模式首版；不会自动重写成原生业务后端，也不改动旧版本、旧指针及 PREVIEW/LIVE 数据。

```text
源码根/
  .atoms-source-root
  项目UUID/
    repository.git/                 不可变对象和 refs/atoms/versions/版本UUID
    staging/候选UUID/project/        已封存、接受前重新核对的候选
工作副本根/
  .atoms-source-root
  任务UUID/
    .atoms-source-workspace
    project/                        普通文件副本，不含 .git
```

目录中的标记、所有权、私有权限和租约属于存储协议，不能手工移动、替换或删除。根必须为专用绝对路径，不能复用仓库根、用户主目录或任意已有未标记目录。

## 配置与前提

继续使用 Java 17。需要维护者指定本机 Git 和 Python 3.11+；Python 仅使用标准库，必须支持 POSIX 目录描述符和 `O_NOFOLLOW`。不自动下载安装或查找个人工具配置。

| 环境变量 | 作用 |
|---|---|
| `PROJECT_SOURCE_ENABLED` | 默认 `false`；不启用时无源码协调者、不探测 Git、不创建源码根 |
| `PROJECT_SOURCE_ROOT` | 正式源码的专用绝对路径 |
| `PROJECT_SOURCE_WORK_ROOT` | 工作副本的另一专用绝对路径 |
| `PROJECT_SOURCE_GIT` | Git 可执行文件绝对路径 |
| `PROJECT_SOURCE_PYTHON` | Python 可执行文件绝对路径；解析为实际文件后使用 |

以下是 Spring 配置项（不是新增的环境变量别名）：`atoms.source.max-bytes` 默认 `8589934592`，`atoms.source.reserve-bytes` 默认 `536870912`，`atoms.source.operation-timeout-seconds` 默认 `300`、有效范围 1–300。降低预算可用于维护者故障演练；调整已批准预算需另行评审。

启用会取得本机根租约和数据库单协调者租约，先核对遗留操作再接收新请求。不支持多个平台写入进程并发管理同一个数据库/源码根。配置开关不会把新能力自动接到旧生成器或网页；当前仅提供内部集成入口。

文件策略固定为：UTF-8 文本、最多 512 文件、单文件 2 MiB、整树 16 MiB、路径 240 UTF-8 字节/16 层。暂不支持二进制资源；拒绝而非静默丢弃。排除 `.git`、Agent 配置、缓存、构建产物、运行数据、真实凭据及异常文件类型；可执行位仅允许既定 `backend/mvnw` 路径。策略扫描不等于任意文本绝无秘密的证明。

## 内部调用顺序

内部服务位于 `dev.atoms.demo.source`，不是对外 REST 契约。后续模块应通过窄适配器集成，不能让网页传入绝对路径、Git SHA、命令行或自报摘要来接受版本。

| 阶段 | 当前实现入口与约束 |
|---|---|
| 初始化 | `SourceCoordinator.initialize`；受控完整树、所有者、项目、幂等键；返回持久操作及本次完成 Future |
| 导入旧工程 | `LegacySourceImporter.prepare`；固定旧版本与模板摘要；得到的操作和树交给协调者 |
| 跨模块完整读取 | `ProjectSourceReadGateway.read(owner, project, version)`；返回指定已发布版本的 `Snapshot(version, tree)`，不接受绝对路径或 Git 对象 ID |
| 包内查询 | `SourceQuery.versions/snapshot/tree/file/diff`；平台版本 UUID、当前所有者校验、不可变树摘要复核 |
| 准备修改 | `SourceWorkspaceStore.prepare`；固定源码版本/修订号及任务 UUID；`checked` 仅向内部适配器给出已核对路径 |
| 封存 | 确认 Agent 已结束后调用 `SourceCandidateStore.seal`；重新扫描并复制到受控 staging，不信任模型自报的路径/hash |
| 接受 | `SourceAcceptance.prepare` 后 `SourceCoordinator.submit`；持久幂等、再授权及基线 CAS；失败不能覆盖当前版本 |
| 取消 | `ProjectSourceService.cancel`；反映实际发布状态，不能把提交后的结果伪装成取消 |
| 恢复 | `SourceRestoration.prepare` 后交给协调者；创建新版本，记录当前父版本和历史来源，不执行 SQL |

协调者有一个磁盘 Worker，待处理操作上限 64。工作副本和候选句柄也各自有 64 的内存上限；接收候选后释放句柄，磁盘证据保留。幂等重试先读取持久记录，不要求仍持有已释放句柄。重复请求可能返回仍在处理的状态，需要查询操作；Future 的存在不等于已经提交。

源码版本 `COMMITTED` 只意味着源码已保存，不表示编译、启动、健康检查或业务验收成功。源码差异的正文最多 128 KiB，返回截断标记及完整文件统计，仅作展示，不可当作可应用补丁。

完整读取复用包内查询的读前/读后授权、引用、SHA-256、文件数量和字节数校验；返回的文件列表及字节内容不可被调用方原地修改。读取历史版不会切换当前版本，不初始化缺失存储，也不运行工程。调用方不得持有数据库事务进行此读取；返回值不是执行授权，后续构建、启动或下载仍须重新检查当前所有者和各自准入条件。

## 超时、容量与故障

单个 Git/Python 子进程最多 60 秒；多步骤源码操作共享最多 300 秒的执行预算，不因逐个文件而重新计时。确认退出的有界收尾等待可能使实际返回时间略长，不能把超时当作操作系统已终止进程的证明。

这些预算仅约束源码读写，不更改已有模型的 tokens 上限、API 请求超时或整轮生成超时。

8 GiB 是源码根内 Git/暂存文件的逻辑大小准入；工作副本根参与可用空间检查，不计入该源码根总和。写入前检查两个根所在文件系统至少余下 512 MiB 加预计写入量。它不是操作系统硬配额：外部写入仍可能耗尽磁盘，失败时保留原版本，不自动清理历史或未知目录。

`source_operation_finished` 日志包含项目/操作 ID、状态、稳定错误码、耗时；`source_operation_reconciled` 记录启动核对结果。不输出源码、服务器绝对路径、原始工具错误或凭据。数据库操作的 `execution_pending` 表示该次执行是否仍缺少结束证据。

遇到 `NEEDS_RECONCILIATION`、根身份不符或对象损坏时，停止该项目写入并由维护者核查。不能因为候选文件存在就发布它，也不能仅凭旧 PID 杀进程或清除阻断。当前没有自动强制解锁、孤儿进程回收或 GC 工具；无可靠结束证据时继续保留阻断。

## 备份、恢复与安全关闭

1. 停止接收源码写入，并正常停止唯一协调者/平台；若已启用 Agent，先停止 Agent，再停止源码协调者。确认自有操作已经结束；遇到不确定执行先核查，不能边写边复制当作一致备份。
2. 在同一个停写窗口备份 PostgreSQL（含原项目归属、源码及已启用模块的任务/租约/事件表）、整个源码根及必要的工作副本证据。仅备份 Git 或 PG 任一侧都不足以恢复版本。
3. 保存各根的路径映射、标记、权限和工具版本。备份内也可能含业务源码，应按私有资料保护；密钥配置另行安全备份，不放入工程或 Git。
4. 在维护环境恢复匹配的一组 PG/Git 数据，保留标记与私有权限；只启动一个协调者，核对版本引用、SHA-256、文件数、字节数及操作状态，再允许写入。
5. 回退新功能时先安全停止依赖源码的 Agent，再设置 `PROJECT_SOURCE_ENABLED=false` 并重启，保留 Git、候选和全部已应用迁移的数据。不要通过删表、重写旧迁移或删除仓库回退。旧网页继续原流程；待核对的新任务不能通过回退到不识别租约的旧写入实现来强制解锁。

恢复源码只产生新源码版本，不回退数据库迁移或业务数据。未来执行模块必须单独检查代码与数据结构兼容性。

## 边界与下一阶段

普通目录、环境白名单和独立进程不是操作系统沙箱。同系统用户的任意 Agent/后端仍可能访问该用户权限范围内的文件和网络，因此本模块不自动执行项目脚本；封存前必须确认 Agent 已停写。
