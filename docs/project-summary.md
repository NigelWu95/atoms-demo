# Atoms Demo 项目实现说明

本项目围绕 AI 应用搭建平台的核心体验，实现“描述需求 → 智能体规划与生成 → 可交互预览 → 数据保存 → 继续修改 → 显式发布”的主流程。目标是交付一个能够真实调用模型、生成代码并运行应用的产品原型，而不是静态页面复刻，也不尝试在首版覆盖完整商业平台。

当前定位是**具备真实生成与持久化能力的受控 Web 应用搭建 Demo**。生成业务代码仍是受限 HTML/CSS/JavaScript 加 SDK；选定版本可下载为 Vue + Spring Boot 17 + PostgreSQL 完整固定工程并脱离平台运行。平台本地已支持冻结工程、异步构建、真实独立进程启停、独立数据库持久化与实际 JAR 预览；不是任意生成式后端或生产托管执行平台。

## 一 实现思路与关键取舍

### 先实现一条真实可用的核心流程

用户进入网站后建立访客会话，创建项目并提交需求。后端先把生成任务保存到数据库，再由后台 Worker 执行；页面通过 SSE 接收持久化的阶段事件。模型输出通过产物校验后，系统保存新的代码快照，并在工作台中加载交互预览。

应用中的待办、表单或游戏状态通过 SDK 保存到服务端，刷新后可以恢复。用户继续提出修改需求时，模型读取当前版本源码并生成新版本；失败不会覆盖旧版本。发布操作将公开链接绑定到指定版本，后续编辑不会自动改变线上版本。

这里区分三件事：模型完成输出、平台保存合规版本、应用实际满足用户需求。它们不是同一个成功标准。

### 技术栈优先服务于交付与一致性

前端使用 Vue 3、TypeScript、Vite 和 Pinia，承载首页、项目管理、对话工作台、源码视图和应用预览；后端使用 Java 17、Spring Boot、Spring Security 和 Spring Session，处理身份、授权、任务、版本及持久化。PostgreSQL 保存会话、项目、代码快照、运行事件、应用状态和模型调用记账，Flyway 管理增量迁移。

选择 Spring Boot + Vue，主要是契合既定技术偏好，并把事务、会话和任务管理放在一套清晰的工程内。首版没有足够证据表明更换为 Go 能提高交付成功率，因此不为语言本身增加迁移成本。未来如果执行服务需要独立扩容，可以沿现有接口拆分，并不要求先重写整个后端。

选择 PostgreSQL 的主要原因也不是免费，而是复用同一个关系数据库完成所有者隔离、幂等约束、修订号冲突检查和原子提交，减少额外组件。这里并不依赖 PostgreSQL 独有的 AI 能力，也没有给每个生成应用动态建表；其他关系数据库同样可以承载类似设计，但需要适配现有 SQL、锁和迁移。

### 用有界工作流表达 Agent 能力

生成流程由真实的 Planner、Builder 调用和程序校验组成：Planner 输出结构化计划，Builder 生成固定格式的完整应用产物；构建结果在 JSON 或产物契约校验失败时，最多额外调用一次修复。

这是一套可观察、可终止的编排流程，不是多个自主 Agent 自由协作。每轮通常需要两次模型请求，有限修复时最多三次；认证失败、请求超时和输出截断不进行盲目自动重试。SSE 展示的是实际任务阶段和结果，不是模拟进度，也不是模型逐 token 输出。

模型网关固定接入 DeepSeek，密钥只保存在服务端。开发阶段的 AI 编程助手用于辅助拆解需求、实现代码和编写测试；运行时的 DeepSeek 则用于响应平台用户的生成请求，两者用途和额度相互独立。

### 限定生成产物与执行范围

首版约定应用产物包含 manifest、HTML、CSS、JavaScript 和初始状态。生成代码在带有 sandbox 与 CSP 限制的 iframe 中运行，通过受限消息桥调用状态读写 SDK，不直接访问平台会话、数据库凭据或任意后端接口。

这一取舍省去了任意依赖安装、前端工程编译、服务器代码执行和容器调度，适合待办、计算器、表单草稿和小游戏等轻量应用。代价是不能直接生成任意 Vue/React 工程、安装 npm 包、连接任意外部服务或执行自定义后端逻辑。浏览器沙箱也不等同于进程隔离，不能承诺完全隔离恶意代码的 CPU、内存或导航行为。

### 先交付可带走的固定工程，再扩展平台执行架构

新增工程下载复用不可变版本与所有者权限，组合白名单固定模板输出有界 ZIP，而不是把平台整个目录打包。包内提供 Vue 外壳、独立 Spring Boot 数据服务、迁移、测试和构建启动入口；只携带源码与初始数据，不复制平台会话、业务状态、对话或密钥。独立运行不再依赖平台保存数据，但沿用访客隔离与受限 iframe，不自动变成共享业务数据库或任意后端生成。

固定模板使构建输入、权限和验收范围可控；用户也能在解压后修改外壳与后端重新构建。代价是需要自行准备工具链、独立运行/测试数据库和外部配置，而且修改不会自动同步回平台。下载服务本身不执行代码；本机构建由单独的持久队列、工作区和受控进程监督器执行。使用方法见[工程下载说明](https://github.com/NigelWu95/atoms-demo/blob/main/docs/project-export.md)。

本机构建先冻结选定版本和实际模板内容，再在私有新目录完整执行前后端检查与打包。成功时保存源码包、JAR 与实际运行资源身份，按 buildId 下载同一份冻结 ZIP，不在下载时改用新模板。队列、幂等提交、取消、阶段、重启中断和历史记录都持久化；退出未知时保留执行槽，不猜测进程已死或自动重跑。

预览/下载一致性进一步落实到主入口：只有本机运行预览完成身份校验和握手，才开放“下载预览工程 ZIP”，目标取自该进程的 buildId，而不是最新构建或当前模板。停止、预览错误及项目/版本/所有者切换会取消下载资格与在途请求。旧版本源码导出直接展示并明确标注未绑定运行预览；共享预览与现有公网发布不冒充独立工程验收。下载带走同一份业务代码和固定后端源码，但不复制实际业务数据或凭据。

本机流程提供“运行应用”主按钮，串联复用/构建、启动新进程和真实预览，手动构建/启停仍可用；页面打开/刷新不会自动运行，旧版本不会被自动停止，未知请求要求明确确认。已在专用库验证一键复用启动及下载，日常环境仍需准备单独运行库并启用开关：当前 Docker 管理接口无响应，未自动修改日常配置或重启后端。没有新增服务器部署或多主机实例管理。

按用户选择直接使用本机进程，不强制容器；仅适用于可信本地环境和固定工具链，不是 OS 沙箱。构建默认关闭、一个执行槽、四个活动任务、十分钟期限；模板测试库专用且串行。独立运行另需显式启用：每项目最多一个、全局两个实例，管理员预备的配置池永久绑定项目，不自动建库。实例预览读取真实 JAR，运行数据不与 PREVIEW/LIVE 混用；下载绑定同一 buildId，停止重启保留数据。见[实例说明](https://github.com/NigelWu95/atoms-demo/blob/main/docs/app-runtime.md)和[原生进程取舍](https://github.com/NigelWu95/atoms-demo/blob/main/docs/decisions/013-native-process-engineering-preview.md)。

### 将代码版本与业务数据分开

每次成功生成或修改都会保存不可变代码快照，应用业务状态则独立存储。这样可以保留版本历史，也避免一次代码更新直接清空已有数据。修订号检查防止旧页面静默覆盖新数据，幂等键用于确认同一次写操作，而不是无条件重复执行。

预览状态与公开应用状态分为 PREVIEW 和 LIVE，并按项目与访问者隔离。当前公开应用的不同访客各自保存数据，不是多人共享同一业务数据库；代码更新也没有通用的数据结构迁移能力。

### 访客身份降低体验门槛

首版采用服务端访客身份和持久会话，不要求用户先注册或配置 API Key。私有项目仍按所有者鉴权，不会因为知道项目地址就获得访问权限。

未绑定邮箱的访客清除 Cookie、更换浏览器或会话失效后，仍无法自行找回原项目。现已增加可选邮箱验证码注册/登录：新邮箱升级同一个 UUID，保留已有项目；已有邮箱登录原账号，不自动合并当前访客。退出与跨标签页切换清理旧状态，保留服务端数据；OAuth 暂缓。个人 QQ SMTP 与数据库原子预算适合低流量 Demo；单次真实送达与验证码登录已通过，规模化投递、隐私删除和公网 HTTPS 仍待完善。按用户要求增加默认关闭的 HTTP 演示开关，显式开启后允许明文账号认证，但不代表正式账号服务具备传输安全；实际云端配置未改变。详见[邮箱说明](https://github.com/NigelWu95/atoms-demo/blob/main/docs/email-accounts.md)。

### 单服务器部署与路径发布

部署采用 Nginx、Spring Boot 单实例和原生 PostgreSQL。Nginx 提供前端静态资源与 API 代理，已发布应用通过 `/a/<slug>` 访问；不为每个项目启动独立端口、容器、域名或 ngrok 进程。

这使部署包更容易在一台服务器上启动，也复用了预览、版本和数据能力。代价是平台与应用共享服务资源和故障范围，不能把项目级数据隔离描述为独立部署隔离。生成器目前只有一个 Worker，不支持直接增加多个后端实例来扩容。

### 真实验收与质量现状

10 月 16 日邮箱账号初版验收：平台后端 131 单元 + 95 PostgreSQL / HTTP 集成、前端 208 单元，以及基础工作台 16 项、应用运行时 33 项真实 Chrome 用例全部通过。新增用例覆盖注册保留项目、重登、退出、跨标签页和旧会话撤销；按安全/浏览器验收流程发现并修复了 iframe 焦点触发多余身份复核的问题。HTTP 演示适配后重新通过后端 134 单元 + 96 集成、前端 208 单元及类型/静态/构建检查、邮箱 Chrome 2 项；没有把此前的 16 + 33 项记作再次全量运行。

用户随后完成私有配置并指定受控 Outlook 收件邮箱。生产 SMTP 的 TLS/认证通过，真实页面发送一次邮件返回 201；用户收信并自行输入验证码后返回 200，并确认测试 OK。没有读取收件箱或记录验证码，也没有批量发信；真实邮件下退出重登尚未单独复测。详见[账号验收记录](https://github.com/NigelWu95/atoms-demo/blob/main/docs/design/email-accounts/verification.md)。

本地真实模型已完成“生成待办 → 新增和完成任务 → 刷新恢复 → 修改生成 V2 → 筛选且保留原数据”。云端真实模型已完成 2048 生成、生成中刷新后继续观察任务、游戏合并计分以及状态保存和刷新恢复。

早期发布构建曾通过前端 112 项、后端 26 项单元与 50 项 PostgreSQL 集成测试、3 项打包测试及基础检查；当时发布包 3 项浏览器验收通过，npm audit 为 0 已知漏洞。这是历史证据，不代表本次重新执行了漏洞审计，也不是当前测试总数。浏览器与真实模型验收单独记录，见[验收记录](https://github.com/NigelWu95/atoms-demo/blob/main/docs/verification.md)和[云端部署记录](https://github.com/NigelWu95/atoms-demo/blob/main/docs/cloud-deployment.md)。

10 月 11 日的 18 项本地运行时 Chrome 回归覆盖生成状态显示、历史恢复、数据保留与发布指针不变。本次正式包已推送 GitHub 并升级云端，新增 V010 迁移，保留原有项目、版本、数据和配置。公网独立浏览器验证了新版资源、创建/列表/刷新、恢复接口输入校验和权限边界；没有执行云端有效恢复或新一轮模型生成。升级前备份并验证了旧程序兼容新 schema，模型累计记账在此次部署前后均为 18 / 100。

真实调用也暴露了生成质量问题：一次构建在 16,840 tokens 上限下被截断，其中 16,266 tokens 用于推理。10 月 13 日部署已按最新确认设为 **163840 tokens / 单次 300 秒 / 整轮 900 秒**，线上累计上限 100 次，当时已用 18 次；本地上限 10000 次未同步到公网。额度包含推理与最终输出，次数也不是金额预算；本次没有发起新的付费模型验收。

本机构建模块进一步通过平台后端 115 项单元 + 77 项集成、前端 159 项单元以及专用 Chrome 2 项完整场景，包含多尺寸与无障碍检查。真实 API 构建的 ZIP 在另一新目录完成全流程构建，两份 JAR 的运行身份相同且分别保存、刷新和进程重启后恢复数据；平台被强制终止后旧任务不重跑，退出证明核验后新任务可以继续。磁盘不足、依赖目录缺失、验收入口未就绪等首次失败也保留在[构建验证记录](https://github.com/NigelWu95/atoms-demo/blob/main/docs/workspace-build-verification.md)，没有调低门槛或跳过测试来宣称成功。

10 月 14 日独立实例模块完成平台 123 单元 + 83 PostgreSQL 集成、前端 167 单元、真实进程监督 4 项，以及基础工作台 14 项和运行时 33 项 Chrome 回归；后者由原 20 项拆分多尺寸检查而来，保留原断言与超时。两份真实 JAR 使用独立运行库，实际实例预览完成保存、刷新、停止重启和同构建 ZIP 摘要校验；手机实际画面已检查。失败与修正、默认关闭及本地/云端边界见[实例验收记录](https://github.com/NigelWu95/atoms-demo/blob/main/docs/app-runtime-verification.md)。

同日预览/下载一致性补验：前端 181 项与受影响的原 Chrome 12 项通过；主入口下载的真实 ZIP 在新目录完整重建，运行内容身份与预览 JAR 一致。两份程序均实际完成添加、勾选、保存、刷新、重启恢复，五尺寸与无障碍通过。详见上述验收记录 R09；这不代表任意生成业务均已测试，也不表示云端已更新。

### 尚未完成的产品能力

- **账号与协作**：QQ 真实投递和公网 HTTPS 验收、OAuth、邮箱换绑/账号删除、组织与成员权限、实时协作；邮箱注册登录与跨浏览器恢复平台项目已在本地实现。
- **完整托管开发环境**：终端、任意依赖/后端生成、自动数据库供给、OS 级资源隔离、独立实例公网发布和自定义域名仍未完成。固定工程下载、本机固定构建、实例启停与私有预览已实现，不等于完整托管环境。
- **迭代工具**：代码差异对比、可视化编辑、GitHub 授权/双向同步，以及把浏览器错误送回模型的一键修复。工程 ZIP 下载已实现；现有构建契约修复不等同于运行错误自动修复。
- **模型与商业化**：用户自定义模型/API Key、多供应商路由、按用户计费、充值订阅和完整费用预算。
- **生产保障**：公信 HTTPS、按身份限流、总存储配额、数据保留与删除策略、自动异地备份、完整监控告警、容量压测和多实例协调。

源码已上传 GitHub 属于项目交付，**不代表产品已经具备用户项目的 GitHub 授权、导入、导出或双向同步能力**。云端发布闭环、不同类型需求的生成质量和连续修改验收仍是交付收尾项，不应隐藏在后续功能计划中。

## 三 继续投入的扩展方向与优先级

优先级首先看是否影响核心流程成功、数据安全和费用可控，其次看是否改善用户持续使用，再考虑应用类型与商业化范围。新增能力应有明确验收场景，而不是只增加入口。

### P0 完成核心验收并控制开放风险

**首先补齐云端端到端验收。** 用明确的小额模型调用预算，走完新建、生成、交互保存、连续修改、发布、另一访客访问、刷新、更新发布和下线；同时验证活动生成期间取消、服务重启与连接中断。验收重点是旧版本不被失败覆盖、不因重复提交或重连而重复发起付费请求、状态不串项目，而不只是页面能打开。

**其次提高生成稳定性与成本可解释性。** 建立待办、计算器、表单等小型评测集，记录成功率、耗时、推理/最终输出消耗和修改后的数据保留情况。根据结果调整不同阶段的提示词、思考强度和 token 预算，向用户提供明确的失败原因与重试成本；不把持续提高上限或无限重试当作质量方案。

**扩大试用范围前补齐安全与运维底线。** 启用公信 HTTPS，增加身份/IP 频率限制、全局费用保护和项目/状态/报告配额；补上自动备份、恢复演练、任务失败与额度告警。这些事项优先于多模型和团队协作，因为公开访客可以直接消耗平台资源，而当前运行隔离和数据恢复能力仍有限。

### P1 改善留存与修改体验

**账号上线与恢复保障。** 邮箱验证码注册、访客升级和跨浏览器恢复已经在本地接通，一次真实 QQ 投递与验证码登录也已通过。下一步补远程部署与实际 SMTP/登录验收、HTTPS 和隐私/删除流程，再按实际需要增加 OAuth；不能只凭相同邮箱自动合并三方身份。

**差异查看与恢复增强。** 在已实现的历史快照恢复基础上补源码差异、数据兼容性提示和跨页面恢复意图保留；代码恢复仍不等于数据库回滚。

**错误辅助修复。** 将用户确认过的预览错误摘要作为新任务输入，仍受调用预算和修复次数约束。新版本必须重新运行检查，不能因为模型声称已修复就自动通过。

**工程运维与模型配置。** 独立实例及私有真实预览已在本地接上；优先补可审计数据库供给、缓存保留/清理、运行诊断与部署验收，再扩展独立实例公网发布和明确的数据迁移。之后考虑 GitHub 授权/同步；模型侧先做受控供应商选择与密钥安全存储，再考虑任意端点，均不能绕过归属、隐私和费用边界。

### P2 扩展应用范围与服务规模

在固定 Vue/Spring Boot 工程的构建与实例链路稳定后，再支持任意 Vue/React 工程、任意依赖和生成式后端服务。需要升级到真正受隔离的构建与运行环境、资源配额、网络策略、镜像和依赖治理，并重新评估独立应用域名与发布生命周期。这是执行架构扩展，不是简单给每个项目分配一个端口。

多实例任务处理应先补任务租约、心跳、幂等领取与故障接管，再根据容量需求引入队列或独立 Worker。团队权限、协作编辑、计费订阅和应用模板市场则应在核心成功率、隔离与成本机制稳定后推进。

如果只继续投入一小段时间，我会优先交付一条可重复验证的云端完整流程、针对截断与修改失败的质量改进，以及最低限度的开放风险控制。它们直接决定这个 Demo 是否“可用、可信、可继续迭代”。
