# 服务器独立端口发布

2026-10-29 实现平台内置端口入口。应用仍由自己的 Java 进程运行，公网入口负责固定目标转发；不要求安装 Nginx，也不修改平台现有 Nginx 站点。

## 使用

在完整工程工作台点击“应用发布”，选择成功构建，核对迁移并“启动并发布”。进程和端口入口就绪后显示“打开应用”及可复制链接。例如服务器配置内部端口 `18201`、偏移 `10000` 时，访问地址为 `http://192.0.2.10:28201/`。

访问者无需登录平台，应用自身认证仍由应用负责。工作台内预览继续使用原受控代理，下载仍对应相同的源码 / 构建。停止或下线后入口关闭，数据库不删除；重新启动同项目保留端口和数据。退出平台或关闭工作台不下线应用；平台重启不会自动重启应用。

本地不开启此功能时，保留现有 `localhost` / `127.0.0.1` 直接端口访问。

## 维护者配置

在服务器私有 `/etc/atoms-demo/application.properties` 添加：

```properties
PROJECT_PUBLICATION_ENABLED=true
PROJECT_PUBLICATION_HOST=192.0.2.10
PROJECT_PUBLICATION_BIND_ADDRESS=0.0.0.0
PROJECT_PUBLICATION_PORT_OFFSET=10000
```

需要完整工程执行及交付模块已启用。应用仍监听 `127.0.0.1:18201–18204`；平台在应用就绪后监听 `0.0.0.0:28201–28204`。公网安全组 / 防火墙应允许入口端口；不需要开放内部应用端口、平台 8080 或数据库 5432。配置不能从浏览器请求或 Host / X-Forwarded-* 推导。

当前入口是 HTTP、IPv4；不包含 TLS、域名、WebSocket、流式响应、重定向或任意文件上传。延续完整工程预览的路径 / JSON API 契约：根页面、`/index.html`、`/assets/*` 和 `/api/*`，拒绝管理接口及目录穿越。JSON 请求 / 响应最大 1 MiB、静态响应最大 4 MiB。需要更大的文件或其他协议时须单独设计。

## 登录信息与资源边界

Cookie 按主机而非端口共享，见 [RFC 6265 §8.5](https://httpwg.org/specs/rfc6265.html#section-8.5)。入口只转发本项目命名空间的应用 Cookie，剥离平台及其他应用 Cookie；响应 Cookie 加项目名前缀，移除 Domain，固定 Path=/、HttpOnly、SameSite=Strict。支持应用自身 Bearer 认证或服务端 Cookie 认证；不支持必须由页面脚本读取 Cookie 的认证实现。跨来源写请求被拒绝，不放开 CORS。

固定 CSP 禁止 Worker、嵌套框架、外部脚本及外部连接。转发绑定实际持有的运行、构建和源码，每次请求重新核对；无法确认写入结果时不自动重试。只返回必要的类型 / ETag / 已隔离 Cookie，不转发应用设置的平台安全头或重定向。

最多 4 个入口，共用最多 8 个请求线程，每应用同时最多 4 个请求。JDK HTTP server 在平台启动入口设置每监听器最多 64 个连接、8 个空闲连接、15 秒请求接收和 45 秒响应时限，转发总预算 30 秒。应用停止后通常在下一次 1 秒协调轮询中关闭监听，期间原执行层已拒绝向停止中的进程转发。

这些是 HTTP 入口边界，不是操作系统级进程沙箱。源码、私有配置、运行库及模型额度的既有约束保持不变。
