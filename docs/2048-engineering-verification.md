## 平台修正

- 独立预览只向应用 `/api/` 转发格式和长度受限的显式 Bearer 头；平台 Cookie、平台 CSRF 信息仍不转发。
- 源码检查允许 TypeScript 中未加引号的 `password: string` 类型声明和文档中的明确令牌占位符，继续拒绝真实凭据字面量；保留针对误判与泄漏的回归测试。
- Agent 新任务默认工具轮数从 24 提高到 64，可配置 1–128。已有任务预算不变，数据库约束通过 V031 增量迁移更新。
- 平台连接池默认由 5 改为 16，可用 `DB_POOL_MAX_SIZE` 配置。新旧模块同时开启时，源码、Agent、工程执行、旧构建和旧运行调度器各自可能长期占用一个连接，需要为工作事务和 HTTP 请求留出余量。这是平台池，不改变各生成应用的独立数据库连接配置。
- 停用构建服务后的资源清理使用该调度器启动时的访问策略，避免再次加载已停用配置而导致清理失败；新任务的实时授权检查保持有效。
- 关闭 Vite 开发/预览服务器自带的 CORS 处理，让 `/api` 代理把预检交给后端。实测修复前 `5173` 吞掉 OPTIONS 并返回缺少 `Access-Control-Allow-Origin` 的 204，而后端 `8080` 正确返回 `null`；因此接口客户端能登录、隔离 iframe 中的浏览器却失败。修复不开放任意来源：平台保持同源访问，只有后端验证过的预览能力路径处理隔离页面的来源。
