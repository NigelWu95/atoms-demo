# ADR-012 · 恢复历史代码为新版本

## 状态与范围

2026-10-11，按既有 T32/T33 设计实现历史版本恢复。本轮修改在本地验证，不代表云端已更新。工程导出、独立数据存储和完整工程执行不包含在该能力中。

## 决定

恢复不是修改当前版本或删除后续历史，而是复制选定历史源码生成新版本。例如 V1 → V2 后恢复 V1，创建 V3，`basedOnId=V2`、`restoredFromId=V1`，更新当前指针和项目修订号。源码 hash 可以重复。V010 只为 versions 增加可空恢复来源列和同项目外键，不回填或覆盖历史源码。

`POST /api/projects/{id}/restorations` 仅接受 `sourceVersionId` 和 `expectedProjectRevision`，要求访客会话、CSRF 和稳定的 `Idempotency-Key`。沿用项目行锁与事务幂等服务，先校验所有者再重放原成功结果；新恢复要求无活动生成且项目修订号匹配。并发不同意图只有一个成功，相同意图只创建一行。任何失败都不推进指针或保留不完整幂等占位。

恢复不修改 app_states、publications 或旧预览报告。新版本的已保存检查状态为 UNKNOWN，需要重新观察、保存检查报告和显式发布。旧代码仍可能不兼容现有数据，不能把“不主动清空数据”当作任意数据结构兼容保证。

## 界面与失败恢复

从工作台代码版本下拉框选择历史版本后，点击“恢复此版本”。使用内联确认区说明新版本、数据保留和不自动发布，勾选后才能提交；历史预览仍使用初始数据且不可保存。

提交或结果未知时禁止切换版本，保留原版本、修订号和幂等键，提供“重试原恢复操作”。恢复成功后再读取当前项目，避免历史幂等响应把页面指针切回过期结果；读取失败也保留原意图供安全重试。确定的 4xx 拒绝不切换现有预览，提供显式刷新项目状态。组件卸载后忽略晚到结果。

待确认意图只在当前组件内存中保存。刷新或离开页面不会撤销已提交的恢复，回来先读取服务器当前版本；不能承诺跨页面持久化原恢复请求。没有恢复业务数据的按钮。

## 限制与回退

- 不解除浏览器 sandbox/CSP，不执行模型生成的服务端代码，不改变平台与应用的数据依赖。
- 不新增依赖、模型调用或任意源码写入端点。恢复来源必须是当前所有者同项目已保存的版本。
- 回退保留 V010 和已创建版本，先隐藏恢复入口或回退应用代码；旧 JAR 的 Flyway 校验需另测，不通过删列、删版本或还原数据库来撤销发布。
- 项目列表“已生成”只表示存在已保存当前版本，不等于预览检查通过、已发布或最新修改成功。
