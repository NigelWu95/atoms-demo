# ADR-009 · 版本预览检查与显式报告

## 状态

2026-10-07，本地报告切片已实现。后续 T26 已接通固定版本发布门禁：只接受当前版本最新 PASSED 报告，见 ADR-010。

## 决定

普通工作台与独立私有预览在创建 iframe 前，用 Acorn 8.19.0 按 ES2022、`sourceType: script` 解析 `main.js`，不调用 eval/Function，不放宽宿主 CSP。经典脚本不支持模块 import/export、顶层 return/await；超出 ES2022 的语法也不在首版契约内。语法失败仍可查看源码、保存失败报告，但不请求运行文档。

解析通过仅说明语法有效。真实 SDK 启动后才记录 PASSED；iframe load 不算成功。SDK 初始化异常、window error/unhandledrejection 或连接超时将该次观察锁定 FAILED，后续保存数据成功/重复 ready 不会清除错误。重新加载建立新的观察和通道，旧通道回调不能改变新结果。

界面明确区分“本次观察”和“已保存报告”。用户显式保存，服务端不自动反向执行源码或请求模型。未知响应保留原报告、视口与幂等键重试；期间产生新错误时，先确认原意图，再显式保存新报告，不能偷偷改写同键请求。未保存观察在刷新时丢失，已保存报告不会自动代表之后的运行情况。

报告 POST 和 latest GET 均按所有者/项目/版本授权。新报告只接受当前版本；原成功意图在版本推进后仍可重放，但不会替换后来写入的报告。V008 增量表以递增 ordinal 查询最近保存结果，报告不改变源码、run 状态或项目 revision。严格限制字段、检查枚举、最多 5 条/每条 1000 字符错误，以及 1–10000 整数视口；错误按纯文本展示，不记录完整源码或凭据。

## 取舍与限制

- 浏览器反馈可以被作者伪造，不是安全认证、功能正确性证明或后端授权凭据。后续发布仍须所有者、版本、修订号和活动任务等服务端校验，且检查指定版本最新报告。
- 直接打开 document 不走前端解析，但仍受原 HTTP CSP sandbox 和资源限制；没有将语法检查当作沙箱。
- PASSED 是已观察结果，不设“等待几秒即保证运行无错”的承诺。CPU 死循环、未执行分支、语义错误、全部业务交互不由此证明。
- Acorn 是 MIT 许可的解析器；锁文件原已有该版本，本次声明为直接生产依赖，没有升级传递依赖。打包 JS gzip 从上一轮 53.29 kB 增至 91.88 kB；接受这一 Demo 成本，不声明已完成性能基准。
- 总请求体上限、报告保留/总量配额仍是 T22/上线待办；本次只有结构与单报告内容限制。
- 回退可停止使用报告 UI/API，保留 V008 表和既有数据；不降级/篡改已应用迁移，不删表或业务数据。
