# 默认工程模式与访客开发验收

日期：2026-10-29。本轮按用户要求切换本地日常环境；不包含 GitHub 推送或远程部署。本文保留默认模式切换时的验收范围；随后对用户原有 2048 的完整工程迁移与真实账号验证，见[2048 工程验收记录](https://github.com/NigelWu95/atoms-demo/blob/main/docs/2048-engineering-verification.md)。

## 行为和配置

- `/projects/:id` 默认打开完整工程工作台，访客与邮箱账号均可开发自己的项目。`/engineering` 仍有效，旧版本通过 `/legacy` 查看；旧生成接口返回 `ENGINEERING_MODE_REQUIRED`，不静默回退。
- 首次提交初始化完整 Vue + Spring Boot 工程，再创建 Claude Code 任务。旧工程同时附带原 HTML/CSS/JS 和迁移说明；旧数据不进入模型，也不自动迁入新运行库。
- 源码与配置样例保存为磁盘 Git 快照；PG 保存项目、版本关联、任务、事件、额度及执行状态。数据库密码、模型密钥和邮箱配置不在源码或 ZIP 内。
- 已开启本地 `PROJECT_WORKBENCH_DEFAULT_MODE`、`PROJECT_WORKBENCH_OWNER_ACCESS`。源码、Agent live、执行及交付服务继续开启；并发配置为 4。真实任务总预算为原独立 Agent 额度 18，不是旧生成器的 10000 次 API 额度。
- 本地预先准备 3 组测试库/运行库，加上既有固定映射共 4 组；首次构建自动绑定，停止进程不回收或转给其他项目。平台使用低权限角色，不保存数据库管理员密码。当前绑定上限仍为 4，耗尽时源码开发仍可继续，运行需维护者扩容。
- 个人 Claude 登录、配置和全局 Java 默认未改；平台服务使用项目已有 Java 17.0.14。该进程模式不提供 OS 沙箱，本轮仅在本机开放访客流程。

## 真实任务与保留的失败

使用独立浏览器访客验收，未代替用户操作个人项目。累计新增 3 次真实 Claude Code + DeepSeek 任务：

1. 第一次任务在 Oracle 17.0.5 的子进程观察阶段失败，保留 `NEEDS_RECONCILIATION`、编辑租约、候选目录和额度；没有伪造退出凭据或将候选代码保存为成功版本。现有证据不足以断定具体 JDK 缺陷。平台换用已有的项目私有 17.0.14 后，后续两次任务成功。
2. 访客计数器项目 `740889bd-aaf0-4b6f-aca5-0f19588929be` 首次真实开发保存 V2：Vue 页面调用 Spring Boot `GET /api/counter`、`POST /api/counter/increment`，JdbcTemplate 对 PostgreSQL 执行原子递增，V002 迁移创建业务表。源码没有使用浏览器存储代替业务数据库。
3. V2 的首次构建失败：模型添加的 JUnit 条件注解只识别系统属性，而平台通过 `APP_TEST_CONFIG` 环境变量传入独立测试库，导致数据库测试被跳过。构建门禁如实拒绝；第二次 Claude 任务基于 V2 修改条件注解并保存 V3。文件树核对证实仅 `CounterDatabaseTest.java` 改变，业务源码全部保留。没有通过放宽测试门禁使构建变绿。

V3 的完整构建已通过：前端 21 项、Java 14 项测试全部执行，零失败、零跳过。浏览器操作又发现预览代理拒绝无请求体 POST；直连真实 Java 后端成功递增到 1，证实为代理兼容问题。平台修复仅接受不声明 Content-Type 的空 POST，继续按写操作鉴权，非空请求仍要求合法 JSON。新增两项回归先复现失败，修复后请求/策略/传输/预览生命周期共 21 项通过；未修改生成工程，也未降低测试门禁。

多用户模式下，待核对任务保留原项目锁和并发占位，其他项目可继续；旧未决运行保留运行容量、端口和数据库绑定。维护性核对仍限维护者，不能用普通访客身份清理未知进程。

## 权限、原项目与回归

- 正式浏览器入口完成访客创建项目、首轮初始化和真实任务提交；另一访客读取该项目任务和源码均返回 404。
- 对旧生成接口的新提交返回 409；重复提交恢复仍遵循原幂等行为。
- 用户的 2048 项目 `da180374-d5dc-4dae-a4a3-a7134a3c2689` 保持 V1–V6、6 次成功旧任务、18 条对话，本轮没有为它初始化新工程或提交 Agent。切换入口不等于已经将它的浏览器账号改成后端账号；下一次实际需求才基于旧源码开发新工程。
- 后端定向验证：设置/环境/池/旧源码参考/Claude 适配及初始化共 38 项；跨项目隔离待核对任务 1 项；运行调度/协调/核对 20 项；项目列表集成 4 项通过，均在独立平台测试 schema 运行。
- 前端原有全套测试发现两个受文案和模式接口影响的用例，修正后重跑相关 App 与提交流程共 18 项通过；新增提交测试覆盖初始化、丢失响应的同键重试及身份切换取消。隔离源码副本反转初始化判定后，首轮提交用例确实失败，证明该回归断言有效。日常源码没有被该变异试验修改。
- 类型检查、变更文件 ESLint、Vite 构建通过。工程列表使用批量源码版本元数据，显示“工程已保存”，不把模板/源码保存写成“应用已运行”。
